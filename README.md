# Sell-out 網頁報表

Sell-out BI 兩張報表的網頁版，部署在 GitHub Pages。資料以密碼加密（PBKDF2-SHA256 25 萬次 → AES-256-GCM），repo 與網站上只有加密後的 `docs/data.enc`，沒有原始明細。

| 頁籤 | 內容 |
| --- | --- |
| ① 市場綜合折扣率 | 通路 → 前六碼（售價單獨一欄）；期間可選單月或累計（起迄月份）；「Redermx 分開」時官網、BR4/A13、英爵診所的 Redermx 品牌商品另列一列（同業務《2026市場綜合折扣率》）；前期／本期的銷貨數量、銷貨金額、市價、折扣率；側表各通路折扣率（不受通路篩選影響）。篩選：前期、本期、通路、品牌、產品分類 |
| ② 系列別 by 月 | 系列 → 前三碼 → 前六碼 → 品號；銷售金額、銷售數量兩張矩陣。切換：拆組／未拆組、當月／年累計；篩選：年度、月份、通路、通路類別、產品分類、劑型 |
| ③ 系列別樞紐（月） | 仿 Excel 樞紐分析表：系列別名稱 → 規格前三碼 → 規格前六碼，可像群組一樣點開／收合，每組第一列 Total 小計、依總計排序；欄＝銷貨年月＋總計。切換：拆組／未拆組、銷貨金額／數量；篩選：年度、品牌、通路、通路類別；可匯出 Excel |
| ④ 通路別 | 仿 Sell in 405 版面：通路類別 → 通路 → 系列 → 品號（可展開）；欄＝前期、本期（數量、金額、占比、折扣率）、本年累計、變化（金額差異、成長率、折扣率增減）；可切拆組／未拆組 |
| 資料檢核 | 拆組前後金額差、組包未拆、未對到品號、幣別與其他月份不一致、沒有品項明細的通路 |
| 資料更新 | 上傳新的 sell-out 明細（.xlsx）、通路對照、NS 維度表 CSV，瀏覽器內重算並預覽各月差異；下載加密的 data.enc 發布給所有人 |

每個頁籤都可以按右上「⬇ 下載 Excel」，依目前的篩選條件下載（附「篩選條件」工作表）；「⬇ 全部報表」把 ①～④（依各頁目前的篩選條件）和資料檢核放在同一個 Excel。資料更新頁另可下載完整拆組明細（有篩選鈕）。

Excel 是有格式的版本（ExcelJS，按下載時才從 cdnjs 載入並檢查 SRI；載入失敗時自動改用無格式版本）：標題列底色、小計列粗體、總計列、千分位與百分比格式、凍結標題；樹狀報表（①②③④）設定了 Excel 大綱群組，可用左上角的 1／2／3／4 收合到通路、系列、前三碼等層級；網頁上標黃的格子在 Excel 也標黃。

右上「含暫用 BOM」＝Power Query 的 UseTempBOM：預設關閉＝只用 NS BOM（加補充 BOM），與業務參考值口徑一致；打開＝NS 缺 BOM 的組包再用組合單／產品代碼拆解補上。

## 邏輯

照 `SellOut報表/06_程式碼/PowerQuery` 01–05 實作：`build/build_data.py` 打包維度表與未拆組明細，拆組在網頁端 `docs/data.js` 執行（內建資料與上傳資料走同一套程式）：

- 售價＝NS Base Price × 1.05；市價＝拆組後數量 × 售價；折扣率＝銷貨金額 ÷ 市價（分母 0 顯示空白）
- 拆組：數量 × 用量，金額依「成分售價 × 用量」比例分攤，最多兩層；拆不了的組包標「組包未拆」
- 品牌：產品代碼大寫 X 開頭＝Redermx；PB／PA／PT 促銷組的前三碼、前六碼＝「組合包」

驗收：`python build/build_data.py --check` 會印出 2026/01 各通路折扣率（網站口徑，只用 NS BOM／含暫用 BOM），和網站顯示一致。

## 裸瓶對應正貨

NS 組包 BOM 的成分常是裸瓶（半成品）。拆組後改以對應的**正貨品號**顯示（品名、系列跟正貨），**市價仍用裸瓶（BOM 成分）售價**——與業務提供的《2026市場綜合折扣率》、舊報表口徑一致。對應規則：同前六碼、正貨、啟用、有售價，且品名（去掉空白與「-裸瓶」）相同或開頭相同；多個候選時取規格版本相同、A 款、品號較新者。品名對不到的保留裸瓶。對應結果與需確認的項目（規格版本不同、找不到正貨）列在「資料檢核 → 裸瓶對應正貨」。手動指定：編輯 `build/裸瓶對照.csv`（裸瓶品號,正貨品號）或在「資料更新」上傳同格式 CSV。

> 2026-10-08 起口徑與業務提供的《2026市場綜合折扣率》一致（裸瓶原售價＋只用 NS BOM）；少數差異來自參考檔另外拆了 NS 沒有 BOM 的組包，以及手動數值。核對明細請看內部資料，不寫在這裡（repo 是公開的）。

## 通路類別調整

`build/通路類別調整.csv`（通路別,通路名稱,通路類別,說明）覆蓋資料包 D_Channel 的通路名稱與通路類別（留空＝不改；通路名稱相同的通路別會合併成一列）。目前：員購、企業團購 → 類別「線上自營」，通路名稱不變（各自一列）。

## 補充 BOM

NS 沒有 BOM、但業務指定要拆的組包，寫在 `build/補充BOM.csv`（組包品號,成分品號,用量,分攤比例），只用 NS BOM 與含暫用 BOM 兩種模式都會套用；NS 補上正式 BOM 後以 NS 為準。目前：29824060＝QRS005A（122161050003）×3。

## 系列名稱

報表的系列名稱一律用 `build/系列對照.csv` 統一（例：NS 的「玻尿酸」「玻尿酸保濕系列」→ 玻尿酸保濕；「潤透光美白系列」已更名 → 超微C美白）；對照表沒有的名稱自動去掉結尾「系列」。NS 系列改名時在這張表加一列，或在網頁「資料更新」下載系列對照表、修改後上傳。

## 每月更新

**方法一：網頁上傳（不需要 Python）**

1. 登入報表 →「資料更新」→ 拖入新的 sell-out 明細 .xlsx（有新通路時，先下載通路對照表加一列，一起上傳）
2. 檢查預覽的各月差異與警告，按「套用到報表」
3. 按「下載加密資料檔 data.enc」，到 GitHub 的 `docs` 資料夾上傳覆蓋、Commit，約 1 分鐘後所有人看到新資料

**方法二：本機程式**（用電腦上的原始資料整份重建，會取代網頁上傳發布的版本；報表內容沒有變化時不會發布，`build/` 的對照表 CSV 有修改會一起推上 GitHub）

1. 新的 sell-out 明細放進 `SellOut報表/03_原始資料_業務提供`（舊版移到子資料夾）。建置會自動取該資料夾裡**修改時間最新**、檔名含 SellOut 的明細檔（排除彙總表／業績總表、子資料夾不算）；要指定別的檔案用 `--sellout`
2. 有執行 NS 維度表匯出時（`05_資料包/NS匯出` 有 D_Item.csv、D_BOM.csv、D_BOM_補.csv），會自動改用匯出的檔案，否則用資料包
3. 點 `更新報表資料.bat`：重建 `docs/data.enc` 並 push，GitHub Pages 約 1 分鐘後更新

密碼放在 `build/password.txt`（不進版控），或設定環境變數 `SELLOUT_PASSWORD`。換密碼：改檔案後重跑一次，之後發布的資料就改用新密碼。注意 repo 是公開的，**舊版 data.enc 仍留在 git 歷史裡，用舊密碼還是打得開**；如果是因為密碼外流才換，必須清除 git 歷史（或刪掉 repo 重建後重新發布），不能只換密碼。

需求：Python 3.10+、`openpyxl`、`cryptography`。
